2026-11-20 (Friday): Fake PDF-Reader Download Uses Browser-in-the-Browser Window to Deliver Packages Abusing RMM Software

AUTHOR: 

- Keerthiraj Nagaraj

NOTES:

- Active campaign, 49 pages seen 2026-11-01 to 2026-11-14, all built from one page template: a ~2.1-2.5 MB inline page titled PDF Viewer that renders a fake browser-in-the-browser (BitB) window with a spoofed address bar and "Download and launch your PDF Reader software" steps.
- The attackers are abusing legitimate Remote Monitoring and Management (RMM) software.
  -- The payload is a legitimate, vendor-built remote-management installer: ScreenConnect cloud instances (17 distinct) on most pages, a FleetDeck agent on one page and one look-alike ScreenConnect host. Antivirus sees a trusted admin tool, and the victim only has to run the downloaded file.
- One kit, two hosting clusters. 
  -- Cluster A: 25 pages on 5 workers[.]dev accounts, one RMM instance and one Telegram bot for all of them.
  -- Cluster B: 24 pages on attacker-registered domains and third-party sites, with 16 RMM instances and 11 Telegram bots. The clusters share the template and a hard-coded trap host, but no instance, bot or chat ID; whether one actor runs both is not proven.
- Every page tells an operator about each visitor through a Telegram bot (IP, city, ISP, screen size, user agent) and hides from scanners: crawlers, headless browsers and cloud IPs get a fake "scheduled maintenance" page whose button starts a CPU and memory exhaustion loop.
- Only the FleetDeck installer was captured by our crawler; it hashes identically to a sample downloaded separately in an isolated VM (SHA256 5393b2ec...a074b). It installs a Windows service. ScreenConnect installers were not captured, so the remote-access claim for those pages rests on the product's function, not on a captured binary.

DETAILS:

- Attack Chain
  1. Lure page loads. The victim reaches a page (delivery route unknown: no email or ad parameters captured) that shows a browser window drawn inside the real tab, with an address bar showing a popular PDF vendor's download URL. Window chrome adapts to the visitor's browser. Non-Windows visitors see "Windows Computer Required".
  2. Silent installer download. On DOMContentLoaded, a hidden <a download> is clicked and the browser fetches the RMM installer from hxxps[://]<instance>.screenconnect[.]com/Bin/ScreenConnect.ClientSetup.<exe|msi>?e=Access&y=Guest&c=<group>. A code comment left in the template reads "Auto-download file on page load (sample URL) ... Change this URL to your file".
  3. Social engineering to execute. The page shows a progress bar and tells the victim to open Downloads and double-click pdf_Reader_en_install.msi. That name differs from the real downloaded name (ScreenConnect.ClientSetup.*): the page relies on any fresh installer being run.
  4. Operator alert. The page calls ipapi[.]co/json and posts the visitor details to the Telegram Bot API, in a message titled New Visitor Alert - MSI Page, so the operator learns who just arrived and can time the connection.
  5. Remote access. The installer is pre-bound to the operator's tenant (e=Access builds the unattended-access client; the c= fields carry the operator's group label). Once run, the machine registers to the operator's tenant (product function; not captured in our data).

Command and Control -- T1219 -- Legitimate signed RMM clients bound to operator tenants (ScreenConnect e=Access, FleetDeck agent)

Two Clusters, One Kit

- Shared: identical page template (same title, fake address string, lure file name, kit comments, dead sub-requests such as /m/js/utils.js and /config_recaptcha_public.php) and an identical hard-coded host fragment, JFWWI7GrPozJiIEC0tMv.codesphsere[.]ru/WZhZ, present in all 12 page DOMs we sampled from both clusters. The variable is unused in the saved pages, so it shows common code rather than a common operator.
- Different: no RMM instance; Telegram bot or chat ID is shared between clusters.
- Cluster A: 25 pages, 5 Workers accounts (8, 7, 6, 3 and 1 pages), 1 RMM instance, 1 bot. The group label in the installer URL changed between waves (Nov 1-7 and Nov 12-13).
- Cluster B: 24 pages (8 pages on 7 attacker-registered domains, 15 on third-party sites, 1 on Vercel). It is not 24 isolated deployments: one RMM instance is used on 3 sites and another on 2 sites with the same bot, so a few operators appear to control several sites each.
- Reading: a reused kit (sold, leaked or shared) with at least two operator tracks; same actor not proven (Figure 2).

RMM Software Abuse

- ScreenConnect: 17 distinct cloud instances, each used as the source of the installer. The tenant behind the Workers pages answers with the stock ScreenConnect guest page, vendor-hosted, with no company branding, still live on 2026-11-17; this alone is not proof of abuse. We could not tell whether tenants are attacker-created trials or hijacked real tenants.
- FleetDeck: one page. The crawler recorded lure page (200) -> agent.fleetdeck[.]io/8iXft6dXyVjkehwKi9qwgs?win (302) -> agentinstall.fleetdeck[.]io/fleetdeck-agent-8iXft6dXyVjkehwKi9qwgs.exe (200, 4,391,192 bytes, Figure 4). Static strings show it is the FleetDeck Agent installer and installs fleetdeck_agent_svc.exe as a service. The enrollment token appears only in the URL and file name, not inside the binary, so it presumably selects the tenant at install time (inference). 24 VirusTotal engines flag the file at first submission, mostly with RemoteAdmin/PUA labels, so it reads as an unwanted remote-admin tool, not a custom implant.
- Look-alike host: one page fetches a ScreenConnect client from app.cosscon[.]site, a domain registered 2026-11-04, the day the page was seen.

Infrastructure

- Attacker-registered domains: files-reader-view[.]com (2026-11-07,), darksupport[.]shop (2026-11-11), docprivates[.]shop (2026-10-02), fitarno[.]cloud (2026-09-10), creenlines[.]site (2026-10-30), scalvesonixands[.]site (2026-11-02), betweenhea[.]click (2026-04-16, hosting changed four times since April). Let's Encrypt certificates were issued the same day as registration for three of them.
- Third-party sites: kit dropped into a sub-path of 15 domains of mixed age. Six of them, plus one attacker domain, sit on one hosting provider. Five of the 15 domains were registered in 2026 and one was re-registered on 2026-10-30 and hosts the kit on a subdomain, so some may be attacker-built rather than hacked; we do not claim an intrusion vector.
- Every page hotlinks a vendor logo from a software-review site and a Copilot icon from microsoft[.]ai; these are huntable.

Detection Notes

- External visibility: of the 24 cluster-B pages, 21 were later flagged by outside feeds. None of the 25 Workers pages were flagged externally when we checked.
- Defenders: block the full URLs below (for third-party sites, the path, not the domain), inventory which ScreenConnect/FleetDeck tenants your organisation uses and alert on other tenants, and hunt for a browser-side ipapi.co lookup followed by a POST to api.telegram[.]org. Report tenants to ConnectWise and FleetDeck, bots to Telegram.

INDICATORS:

All URLs were assessed as phishing/malware delivery by our analysis pipeline. ScreenConnect and FleetDeck vendor domains are legitimate services abused by operators: block the specific tenant URLs, not the vendor domains.
