NOTES:

- We identified a previously unreported Rust build of ZionSiphon, an operational technology (OT) sabotage tool linked to the persona 0xICS. 
- This sample is internally versioned as v4 and represents a complete rewrite of the .NET v1 variant that other researchers reported in April 2026. 
- The v4 build targets Israeli water and desalination infrastructure through a four-part host-verification gate that checks for Hebrew locale, Hebrew keyboard layout, hostnames matching Israeli water facilities, and the presence of Supervisory Control and Data Acquisition (SCADA) software directories. 
- When it gets deployed, the malware searches for OT configuration files at fictional paths and attempts to write sabotage parameters to programmable logic controllers (PLCs) over Modbus. 
- The Modbus frames remain malformed, lacking Modbus Application Protocol (MBAP) headers and cyclic redundancy check (CRC) values.

DETAILS

- The v4 binary was compiled on July 26, 2026, using the Rust 1.94.0 stable toolchain. 
- The entire program compiles from a single source file (src\main.rs) and ships with the Program Database (PDB) path "zionsiphon.pdb." No intermediate versions (v2, v3, or v5) have been found, making v4 the only confirmed successor to v1. The build embeds a new actor handle, Telegram @rbinrs, which does not appear in any prior ZionSiphon reporting and has no presence on crates.io or GitHub.

- The targeting gate runs four checks in an OR configuration where any single match triggers the payload. 
- These checks compare the Windows UI language and keyboard layout against 0x40D (Hebrew/Israel), test the hostname against tokens tied to Israeli water facilities, and search for SCADA software directories on disk. 
- If all four fail, the malware logs "Target not matched. Operation restricted to IL indicators. Self-destruct initiated." and removes itself. The v1 variant used "IL ranges" in this string, reflecting its broken IP geolocation approach.

- When the gate passes, the malware walks a hardcoded list of OT configuration file paths and attempts to inject a structured INI block containing dangerous process parameters. 
- These parameters cover chlorination dosing, reverse osmosis pressure, and post-treatment settings. 
- The configuration file paths seem fictional and do not seem to correspond to any real product, a finding that was documented for v1 in April 2026 too. 
- The malware also attempts Modbus writes to PLCs after fingerprinting for S7-1200, M340, and ControlLogix models, but the six-byte write frame lacks both the MBAP header and CRC, making it invalid as both Modbus TCP and Modbus Remote Terminal Unit (RTU) but could disrupt normal functionality.

- The v4 build propagates over USB drives using a ReadMe.pdf.lnk lure file and clears Windows event logs using wevtutil after execution. 
- During self-destruction, a file named target_verify.log is written to the local temp directory and persists through the cleanup routine. 
- The binary also references the name SecurityApplication, possibly as a masquerade identifier. 
- The malware scans for running SCADA processes and applies protocol labels (Modbus, DNP3, S7), though only Modbus communication is implemented.

- Defenders should prioritize the fictional OT configuration file paths listed in the indicators section, as no legitimate software creates these files and they provide high-fidelity detection anchors. 
- The target_verify.log artifact in %LOCALAPPDATA%\Temp persists after self-destruction and is the most reliable host indicator across both versions. 
- On the network side, the malformed six-byte Modbus write frame (function code 0x06, no MBAP header, no CRC) is a distinctive behavioral signature. 
- Organizations in the water and desalination sector should treat the crate-version fingerprint as an additional file-level hunting pivot.
