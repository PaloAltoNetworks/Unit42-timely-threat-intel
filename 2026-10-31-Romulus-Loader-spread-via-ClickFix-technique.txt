2026-10-31 (Saturday): Romulus Loader Spread via ClickFix Technique

- Abhiram Patiballa, Saide Sheikh

NOTES:

- We observed a cluster of IP addresses and URLs associated with Romulus Loader malware
  -- These were part of a ClickFix campaign to spread malware
  -- The infrastructure was still live at the time of writing
- The initial delivery vector includes: 
  -- Malicious ads on compromised websites
  -- Custom GPT pages
- They ask the user to copy a malicious command and run it via Windows Run Dialog box
- The PowerShell command line contains the malicious IP address in decimal format
  -- This is likely an attempt to bypass detection rules which rely on standard IP address formatting
- The initial payload downloaded from the malicious IP address is an MSI installer
  -- The installer contains three stages of obfuscated payloads stored in the MSI's Binary table
- Subsequent stages involve VBScript Custom Actions
  -- These decode and execute embedded PowerShell loaders
  -- They use dual-layer numeric encoding and a byte-sampling steganographic algorithm
  -- The process extracts hidden PE executables from MSI binary table entries
- The malware persists through the RunOnce registry key
- The malware communicates with its C2 server at scridea[.]com/nfront.php over HTTPS
  -- The traffic uses a spoofed Chrome/Vivaldi user-agent string
  -- The  with retry logic and named pipe inter-process communication
- The same URL request to the C2 server for a new file would return a file with a different SHA-256 hash

ADDITIONAL DETAILS:

- A malicious custom GPT or a compromised website with malicious ads directs the victim to:
  -- copy-paste a PowerShell command
  -- The command is designed to retrieve and run an MSI installer file
  -- The potential victim is asked to run the command in a Run dialog window (Win + R)
- The VBScript uses a custom action and queries the binary table to extract encoded PowerShell payload:
  -- The PowerShell file is written a <random>.ps1 file in the %TEMP% directory
  -- The file is executed with "-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden" switches 
  -- The PowerShell file is deleted after execution
- The script accepts an MSI file path from the first command-line argument
- The script opens the specified MSI database and executes an SQL query to retrieve a binary stream from the MSI Binary table
- The extracted byte array is parsed as a PE file and loaded via [Reflection.Assembly]::Load()
- The loaded PE contains an encrypted shellcode payload in its data section
  -- The PE decrypts the shellcode using AES-256-CBC via the CryptoAPI and executes it later
- The decrypted shellcode performs host reconnaissance by:
  -- Querying the host's location via la egitimate service at ipinfo[.]io
  -- Collecting system fingerprinting data including volume serial number 
  -- Retrieving device information via WMI and COM interfaces
- It also exfiltrates the collected data as a base64-encoded POST request to:
 -- hxxps[:]//scridea[.]com/nfront.php 
 -- This uses WinHTTP with the following User-Agent string:
    Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/114.0.0.0 Safari/537.36 Vivaldi/5.3.2679.68
- The unpacked PE contains stack-constructed string references to:
  -- AmsiScanString
  -- AmsiScanBuffer
  -- appbound
  -- dpapi
  -- explorer.exe
  -- LdrLoadDll
  -- msiexec
  -- powershell
  -- Roaming\\
  -- RuntimeBroker.exe
  -- \\System32\\Amsi.dll
  -- \\SysWOW64\\explorer.exe
  -- \\.\\pipe
- These strings are present in:
  -- The code sections of the unpacked PE and reference AMSI bypass
  -- Named pipe construction
  -- Credential or browser data access paths
- Additionally the PE
 -- Implements 10 process injection techniques selectable by a runtime configuration value
 -- Performs AMSI bypass by patching AmsiScanString and AmsiScanBuffer in a suspended RuntimeBroker.exe process
    --- The process injection dispatcher implements 10 distinct techniques selected by a configuration value:
    --- The associated technique IDs are 0, 1, 2, 10, 11, 14, 16, 17, 18 and 20
    --- The default target process is %SystemRoot%\explorer.exe
    --- Techniques 0 through 2 perform process hollowing by:
        ---- Calling NtCreateUserProcess with a suspended creation flag
        ---- Mapping a new section into the target process
        ---- Applying relocation fixups
        ---- Then resuming the main thread

ADDITIONAL FINDINGS:

- We pivoted on the Romulus Loader C2 panel hosted at 151.240.151[.]223
  -- The results revealed the site hosted several different MSI payloads and PowerShell scripts
  -- These appear to be spread via ClickFix social engineering technique
- Pivoting on the SHA-256 hash of the C2 login panel page revealed:
  -- Multiple other IP addresses with similar infrastructure related to Romulus Loader
- The hash of the MSI Installer binary even when requested from the same URL is different every time
- In addition to hosting MSI installers, these IP addresses for Romulus Loader also hosted:
  -- Many PowerShell scripts which target the /app/ path of each IP addresses
- For example:
  -- The URL jasimebeltran[.]design/1 returned a PS script
   -- Decoding the scripts reveals a the decimal encoded PowerShell command like:
      --- hxxp[:]//2549127012/app/222a8c21d35e/ExpertCopyFilesIntoMultipleFoldersLite.msi
- The above MSI installer masquerades as legitimate software 
  -- But it contains malicious DLLs which which are side-loaded loaded into memory
  -- These side-loaded DLLS attempt to execute malicious shellcode
- The IP address at 2549127012 (151.240.151[.]100)is another Romulus Loader webpage
