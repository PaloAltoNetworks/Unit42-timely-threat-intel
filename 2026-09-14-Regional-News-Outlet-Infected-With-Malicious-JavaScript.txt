
2026-09-14 (MONDAY): Regional News Outlet Infected with Malicious JavaScript Delivering ClickFix Prompts Delivering Encrypted Stealc InfoStealer

AUTHOR(S):
- Thomas Story and Jonny Westfall

NOTES:
- An independent regional news outlet has been compromised with malicious JavaScript delivering ClickFix social engineering prompts.
- The final payload is an encrypted, compressed, and then ConfuserEx-encrypted Stealc binary.

DETAILS:

- The infection sequence begins when a user navigates to a compromised independent regional news outlet. In this documented instance, the user accessed the news site through a local library's proxy service, which simply routed them to the infected destination.
- The news site itself is infected with injected malicious JavaScript hosted on chunks[.]cdnsuicaches[.]com. The script contains Russian comments determining execution modes (click, timer, or mouse movement).
- The JavaScript checks for a specific cookie (cookie-captcha-complete). If absent, it serves the ClickFix overlay and sets the cookie to prevent repeat execution.
- The ClickFix social engineering overlay tricks the user into copying and running an obfuscated command via the Windows Run dialog (cmd.exe /c ...).
- This command downloads a PowerShell script (configuration.ps1) from mnl[.]ac (149.255.35[.]135) and executes it by dynamically calling PowerShell (^W^h^E^r^E po*r*e*l.*e) and bypassing the execution policy.
- The configuration.ps1 script contains an encrypted, gzip-compressed payload that unpacks the stage 2 Stealc binary loaded into memory.

Payload Analysis: Execution and Core Capabilities
- The unpacked payload is a highly sophisticated, multi-stage threat utilizing PowerShell to reflectively load heavily obfuscated 32-bit .NET (C#) DLLs. 
- Functioning as a modular command-and-control (C2) backdoor and information stealer, the malware is designed for prolonged, stealthy access.

Stage 1: Loader Mechanisms & Evasion
- The initial execution relies on two distinct PowerShell scripts responsible for decrypting, decompressing, and loading the primary .NET DLLs entirely in memory.

Primary Loader Script
   - Evasion & Mutex: Generates a random GUID, sets it as the console window title, and hides the window using user32.dll!ShowWindowAsync. 
   - It establishes a named mutex, BOyBdSXJMJHWV, to prevent concurrent infections.
   - Payload Extraction & Decryption: A 463,276-character Base64 string is decoded and decrypted using AES-256-CBC (Key: 9422c81325a47a186e9a8e3841c497ba9e4d99d952ca4838e8e21b7b31427109, IV: c846272dc4af802ebcaa0d5753a67027).
   - Decompression & Loading: The decrypted blob is Gzip-decompressed into a 399,360-byte .NET DLL and reflectively loaded into the PowerShell process via [Reflection.Assembly]::Load().
   - Execution: The script invokes a single public static method from an obfuscated namespace. This executes in a while-loop (up to 36 iterations with 15-second sleep intervals) to establish early C2 communication over TLS and inject into csc.exe.

Secondary Loader Script
- Driven by a UUID (BFMB3BDD697FIGENWWKT54K3P6Q7283N), the second script decodes a 515,200-character Base64 blob using AES-256. It dynamically extracts the IV from the first 16 bytes of the ciphertext. 
- Once Gzip-decompressed into a 471,040-byte .NET DLL, it is reflectively loaded and immediately exits its primary thread to operate entirely via injected processes.

Stage 2: Payload Protections & Anti-Analysis
- Before any user code executes, the module initializer (.cctor) triggers a multi-stage runtime protection sequence heavily armored with ConfuserEx (v1.0.0) and custom protections:
   - Constant and String Encryption: All operational strings are replaced with empty literals and resolved at runtime. 
   - A 15,104-byte constant pool is decrypted using a block XOR cipher and an xorshift PRNG seeded with 1627562570.
   - PE Header & In-Place Decryption: The assembly uses VirtualProtect to make PE section headers writable, zeroing out section names and metadata directory entries. 
   - It dynamically XOR-decrypts the code section in memory.
   - Anti-Debugging:
     - Terminates immediately via Environment.FailFast if specific environment variables are detected.
     - A persistent background thread polls Debugger.IsAttached and Debugger.IsLogging every 1,000ms. If a debugger is detected or the thread is suspended, the process terminates.
     - Rapidly calls CheckRemoteDebuggerPresent during the in-place decryption phase.
- Dead Code Injection: Over 58 Func delegate fields and 100+ static methods consist of unreachable code guarded by impossible runtime conditions to bloat the binary and confuse analysis.

Stage 3: Core Capabilities & Behavior
- Process Injection Chain
- The malware utilizes a highly evasive, multi-tier process injection strategy to mask its activity and interact with browser memory:
   - Primary Injection: The executing powershell.exe injects threads into csc.exe, chrome.exe, msedge.exe, and SearchIndexer.exe using NtAllocateVirtualMemoryRemote and NtSetContextThreadRemote.
   - Secondary Injection: The compromised SearchIndexer.exe acts as an intermediary, injecting an MZ-header PE payload into fresh instances of Chrome and Edge.

Credential Theft
- Once inside the browser memory spaces, the payload actively targets local credential and session token stores:
   - ...\Google\Chrome\User Data\Default\Login Data & \Network\Cookies
   - ...\Microsoft\Edge\User Data\Default\Login Data & \Network\Cookies

Persistence
- The malware establishes persistent execution by utilizing a WScript.Shell COM object to drop a shortcut file named h2dk2pdvpn0.lnk into the current user's Startup folder.

Stage 4: Command & Control (C2) Protocol
- The malware establishes HTTP POST communication using a custom, heavily armored binary protocol over HttpWebRequest.
   - Network Encryption: Plaintext payloads are wrapped in 16 to 64 bytes of randomized padding. 
   - A rolling XOR cipher encrypts the payload, where the key mutates progressively based on loop index and position.
   - Integrity: A 4-byte CRC32 checksum (Polynomial 0xEDB88320) is prepended to ensure transmission integrity.
   - Bot Logic:
     1. Beaconing: The handler generates a persistent, random 32-character bot ID and POSTs this to the C2 URL.
     2. Command Handling: If the C2 responds with 0xCA, the malware extracts a 4-byte identifier and decodes a base64 command string.
     3. Execution: The malware pauses for 5,000ms, spawns a hidden cmd.exe process, writes the command to standard input, and reports the output to a secondary endpoint.
     4. Kill Switch: If the C2 responds with 0xF4, the malware executes an immediate Environment.Exit(1).
