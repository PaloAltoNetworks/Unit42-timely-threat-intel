2026-08-11 (TUESDAY): CLICKFIX CAMPAIGN ABUSES MOZILLA FIREFOX BINARY FOR DLL SIDELOADING

AUTHOR:

- Ofek Lahiani

NOTES:

- In recent weeks, we have observed an increase in ClickFix social engineering activity across multiple customers. 
- The campaign delivers KongTuke through DLL sideloading using legitimate signed Mozilla Firefox binaries.
- The threat actor rotates lure domains while maintaining consistent payload infrastructure and tooling.
- The malicious DLLs are written in Rust and masquerade as legitimate Mozilla Firefox components.
- Three malicious DLLs have been identified: mozglue.dll (the initial loader), firefoxupdate.dll (a COM proxy persistence mechanism), and xul.dll (the primary C2 implant).
- The malware uses a domain generation algorithm (DGA) combining infrastructure-themed and security-themed words with numeric suffixes and three TLDs (.com, .net, .lol) to construct C2 domains.
- Post-infection C2 communication occurs over HTTPS with approximately 30-second beacon intervals.
- We identified 128 unique samples of the malicious DLL variants associated with this campaign, including 54 mozglue.dll samples, 9 firefoxupdate.dll samples, and 56 xul.dll samples.

DETAILS:

ATTACK FLOW:

- The victim visits a ClickFix lure website that displays a fake CAPTCHA or verification prompt.
- The page instructs the user to press Win+R and paste a command into the Windows Run dialog.
- The pasted command runs conhost.exe --headless to execute invisibly without displaying a console window.
- cmd.exe runs curl with flags -skLo (silent, ignore SSL errors, follow redirects) to download a tar archive from the payload server.
- The archive is extracted to %LOCALAPPDATA%\Mozilla\Firefox\Updates\ containing approximately 22 files masquerading as Mozilla Firefox components.
- plugin-container.exe (a legitimate signed Mozilla Firefox binary) is executed from the staging directory.
- A .local DLL redirection file (plugin-container.exe.local) forces Windows to load DLLs from the local directory instead of the system path.
- The malicious mozglue.dll is sideloaded instead of the legitimate one (MITRE T1574.002 - DLL Side-Loading).
- The malware establishes C2 communication over HTTPS with approximately 30-second beacon intervals.

DLL SIDELOADING MECHANISM:

- The attack abuses the Windows .local DLL redirection feature.
- A file named plugin-container.exe.local is placed alongside the legitimate plugin-container.exe binary.
- When plugin-container.exe loads, Windows checks for the .local redirection file and prioritizes loading DLLs from the application's local directory.
- The malicious mozglue.dll is loaded instead of the legitimate Mozilla library.
- The staging directory %LOCALAPPDATA%\Mozilla\Firefox\Updates\ contains approximately 22 files designed to mimic a legitimate Firefox installation.
- Key files in the staging directory include:
-- plugin-container.exe (legitimate signed Mozilla binary, used as the sideloading host)
-- mozglue.dll (malicious DLL sideloaded by plugin-container.exe)
-- plugin-container.exe.local (DLL redirection trigger file)
-- firefoxupdate.dll (malicious COM proxy persistence DLL)

POST-INFECTION ACTIVITY:

- Once the malware successfully executes, it spawns a child process of plugin-container.exe to host the malicious activity.
- The malware initiates a repeated automated discovery loop on the host using:
  -- "cmd" /c "systeminfo /FO CSV"
- A second co-loaded implant, xul.dll, serves as the primary C2 agent. It performs extensive host reconnaissance including SMBIOS fingerprinting and WMI enumeration.
- The implant checks for over 30 sandbox and virtualization indicators including VBOX, QEMU, VMware, Hyper-V, Amazon EC2, Google Compute, ANY.RUN, Joe Sandbox, Hybrid Analysis, and Cuckoo.
- It patches NtTraceControl in ntdll.dll to disable ETW tracing, preventing security monitoring from observing the implant's API calls.
- The implant then begins beaconing to multiple C2 domains generated via a DGA over HTTPS with approximately 30-second intervals.

MALWARE ANALYSIS - MOZGLUE.DLL:

- The sample is a 64-bit DLL binary written in Rust targeting Windows operating systems.
- The DLL masquerades as the legitimate Mozilla Firefox component mozglue.dll, exporting matching symbols and embedding spoofed version information for Firefox 139.0.2.0 from Mozilla Corporation.
- On DLL_PROCESS_ATTACH, it checks XOR-obfuscated environment variables SUOMI_WO_WORK (key 0xCC) and SUOMI_AGENT (key 0x73) to route execution between three operational modes:
-- Browser profile manipulation
-- C2 agent communication
-- A watchdog that spawns and monitors child processes under parent PID spoofing
- The DLL hooks IAT entries for exit, _exit, and ExitProcess in the host process, redirecting them to an infinite SleepEx loop to prevent process termination.
- It employs a domain generation algorithm using 25 infrastructure-themed and 24 security-themed words combined with three TLDs (.com, .net, .lol) to construct C2 domains.
- The malware communicates via HTTP POST with JSON-formatted telemetry through dynamically loaded WinHTTP APIs.
- Named mutexes suomi_com_guard_ and suomi_wd_guard_ prefixed to the computer name enforce single-instance execution.

MALWARE ANALYSIS - FIREFOXUPDATE.DLL:

- The sample is a 64-bit DLL binary written in Rust targeting Windows operating systems.
- The DLL functions as a COM proxy stub whose exported DllGetClassObject function intercepts COM object instantiation.
- It constructs the registry path Software\Classes\CLSID\{CLSID}\InProcServer32 under HKEY_LOCAL_MACHINE, reads the legitimate COM server DLL path, loads it via LoadLibraryW, and forwards the COM creation call to the real implementation.
- The binary's PE version resource identifies it as firefoxupdate.dll described as "Mozilla Firefox Update Service" version 139.0.2.0 by "Mozilla Corporation."
- The embedded Rust source path reveals the actual project name persist_stub, indicating this DLL serves as a persistence mechanism.

MALWARE ANALYSIS - XUL.DLL:

- The sample is a 64-bit DLL binary written in Rust targeting Windows operating systems.
- The DLL masquerades as a Mozilla XUL library (xul.dll) and functions as a modular command-and-control implant.
- The binary communicates with 9 domains generated via a domain generation algorithm over HTTPS port 443.
- The DLL exports 7 functions styled after Mozilla XUL conventions: DllMain, XUL_Boot, XUL_Exec, XUL_Init, XUL_InitPlatform, XUL_Load, and xul_Configure.
- The initial handshake is sent as a POST request to /agent/v2/handshake with Content-Type: application/octet-stream and User-Agent: curl/8.7.1.
- Post-handshake communication uses BeaconRequest/BeaconResponse pairs carrying health summaries, task capacity reports, and session directives.
- The implant collects extensive host reconnaissance data including system name, SMBIOS hash, domain membership, OS build string, architecture, integrity level, process ID, IP address, and SMBIOS product identifier.
- It reads the SMBIOS firmware table via GetSystemFirmwareTable and parses detailed hardware information.
- The binary performs sandbox and virtualization detection by checking SMBIOS product strings against over 30 indicators including VBOX, QEMU, VMware, Hyper-V, Amazon EC2, Google Compute, ANY.RUN, Joe Sandbox, Hybrid Analysis, and Cuckoo.
- It disables ETW tracing by patching NtTraceControl in ntdll.dll, changing memory protection to PAGE_READWRITE, writing a patch, then restoring PAGE_EXECUTE_READ.
- Task execution is driven by a WebAssembly runtime built on Wasmtime with the Cranelift code generator.
- Seven built-in module types are referenced: mod-shell, mod-file, mod-cmd, mod-ps, mod-ss, mod-sleep, and mod-persist.
- Task capabilities include shell command execution, file operations, PowerShell execution, screenshot capture, AMSI bypass, and persistence installation.
